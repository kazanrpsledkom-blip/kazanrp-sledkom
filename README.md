# СК Документы: сайт с общей базой, входом и законодательством

Что получится: сайт по адресу `https://ВАШ-ПРОЕКТ.web.app` (бесплатно, без покупки домена), куда сотрудники заходят с любых устройств по логину и паролю. Документы хранятся на серверах Google, права проверяет сервер, а не страница.

Всё это укладывается в бесплатный тариф Firebase Spark: банковская карта не нужна.

## Что внутри

| Файл | Назначение |
|---|---|
| `index.html` | сам сайт: вход, редактор, 19 бланков, журнал, сотрудники, законодательство |
| `firebase-config.js` | сюда вставляются данные вашего проекта (шаг 4) |
| `firestore.rules` | правила базы: кто что видит и меняет (шаг 5) |
| `firebase.json`, `.firebaserc` | настройки публикации |
| `laws/` | тексты законов и правил проекта (Конституция, УК, УПК, ФЗ о СК и другие) |

## Установка по шагам (около 15 минут)

### 1. Создайте проект Firebase
1. Откройте https://console.firebase.google.com и войдите под Google-аккаунтом.
2. «Добавить проект». Название придумайте короткое, например `sk-tatarstan`. От этого названия зависит адрес сайта: `sk-tatarstan.web.app`. Если имя занято, Firebase предложит другое.
3. Google Analytics отключите, он не нужен.

### 2. Включите вход по паролю
«Сборка» (Build) → **Authentication** → «Начать» → вкладка «Способ входа» → **Электронная почта/пароль** → включить → «Сохранить».

### 3. Создайте базу данных
«Сборка» → **Firestore Database** → «Создать базу данных» → режим **рабочий (production)** → регион `eur3` (Европа) или ближайший → «Включить».

### 4. Подключите сайт к проекту
1. «Настройки проекта» (шестерёнка) → вкладка «Общие» → внизу «Ваши приложения» → значок `</>` (веб).
2. Название любое, например `sk-site`. Хостинг на этом шаге не включайте. «Зарегистрировать».
3. Появится блок `firebaseConfig`. Скопируйте значения в файл `firebase-config.js` вместо слов «ВСТАВЬТЕ…».

### 5. Вставьте правила безопасности
Firestore Database → вкладка **Правила** → удалите всё, что там есть → вставьте содержимое файла `firestore.rules` → **Опубликовать**.

Без этого шага база либо закрыта для всех, либо открыта для всех. Пропускать нельзя.

### 6. Опубликуйте сайт (выберите один способ)

**Способ А. Firebase Hosting (адрес `проект.web.app`).**
1. Установите Node.js (https://nodejs.org, версия LTS).
2. Откройте командную строку в папке с этими файлами и выполните по очереди:
   ```
   npm install -g firebase-tools
   firebase login
   firebase use --add
   firebase deploy
   ```
   На `firebase use --add` выберите ваш проект. Команда `deploy` в конце напишет адрес сайта.
3. Если Firebase попросит включить Hosting, согласитесь: он бесплатный.

**Способ Б. Без командной строки (GitHub Pages).**
1. Зарегистрируйтесь на https://github.com, создайте репозиторий (публичный).
2. «Add file» → «Upload files» → перетащите **все файлы и папку `laws`** → «Commit».
3. «Settings» → «Pages» → ветка `main`, папка `/ (root)` → «Save». Через минуту сайт откроется по адресу `https://ваш-ник.github.io/название-репозитория/`.

### 7. Первый запуск
1. Откройте сайт. На экране входа нажмите **«Первый запуск»**.
2. Создайте учётную запись руководителя. Сделайте это сразу после публикации: первый, кто это сделает, становится руководителем, и больше такая кнопка не сработает.
3. В разделе **«Сотрудники»** добавьте остальных (логин, пароль, роль) и отдайте им адрес сайта.

## Роли

- **Руководитель**: всё, включая сотрудников, настройки бланка и счётчиков, аннулирование.
- **Старший состав**: видит все документы, подписывает.
- **Сотрудник**: создаёт и правит свои документы, видит документы с доступом «Все сотрудники».

## Что нужно знать

- **Забытый пароль.** Если при создании сотрудника указан настоящий e-mail, на странице входа работает «Забыли пароль?». Если e-mail не указан, создайте для человека новую учётную запись с другим логином, а старую закройте (Сотрудники → Изменить → «Доступ закрыт»).
- **Свой домен.** Он не обязателен: адрес `проект.web.app` бесплатный и с https. Если когда-нибудь захотите собственный, в Firebase Hosting есть «Добавить домен», но сам домен покупается отдельно.
- **Лимиты бесплатного тарифа.** Примерно 50 000 чтений и 20 000 записей в сутки, 1 ГБ данных. Для штата ГСУ этого с большим запасом. Если лимит исчерпан, Firebase просто останавливает базу до конца периода и ничего не списывает.
- **Законодательство.** Тексты лежат в папке `laws/` обычными файлами. Чтобы обновить, замените нужный `.json` и опубликуйте сайт заново. Тексты взяты с форума проекта как есть, в том числе с его опечатками.
- **Резервные копии.** Журнал регистрации выгружается в CSV, а любой документ скачивается в PDF. Автоматическую выгрузку базы Firebase делает только на платном тарифе.
- **Безопасность.** Логины и пароли проверяет Firebase Authentication, права на документы проверяет база по правилам из `firestore.rules`. Ключи из `firebase-config.js` публичные по замыслу Firebase, это нормально.
